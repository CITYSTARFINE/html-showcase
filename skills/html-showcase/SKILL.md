# HTML 展示页

先读 [README.md](README.md)。执行需求收集时读 [references/intake.md](references/intake.md)；规划和验收时读 [references/tiers.md](references/tiers.md) 的对应等级。学术用途还须读 [references/styles.md](references/styles.md)，该要求按用途触发，不限学术配色。不得更改用户所选等级或七套风格预设定义。

## Workflow

1. **Intake／澄清**：intake 由 `new.py` 完成，对话不再重复问。将用户已有明确选择记录为 `--known`，用 `--questions` 获取下一轮问题并通过原生可点击工具显示，按字段记录实际答案；没有原生选项工具时运行本机按钮向导。顺序为用途 → 风格（含自定义）与美术完成度 → 等级 → 内容来源 → 素材方式及授权 → 验收标准确认。每轮最多三问；T3 另轮二次确认。向导结束只保存需求，不生成页面。
2. **Plan／内容规划**：根据用户材料或已授权检索的可靠来源规划章节、讲述重点、视觉语言及适配所选等级的交互。事实需核验，示例、设想与真实成果分清。学术用途先用一句话提炼核心论点/逻辑主线，将所有章节挂上主线，删除跑偏章节。
3. **视觉方向选择**：必须先提出 2–3 个有差异的构图方向，每个包含名称、一句话描述、关键画面差异点、适用场景。用选择题让用户选定一个，或提出修改意见；不得跳过方向选择直接给最终方案。每个方向的对标及效果依据只能是真实照片、真实画作或真实项目截图：打开原始来源核验，记录链接/路径和核验说明。找不到真实参考时明确标注“暂无对标”，不得用 AI 图补位。自定义风格参考也须如此核验。
4. **视觉方案确认**：用户选定方向后，细化完整方案，缺一不可：① 每屏一句构图草案，写清前景/中景/背景；② 3–5 个决定成败的关键画面及目标效果；③ 逐项素材计划，列制作负责人、SVG/CSS/Canvas 程序化或经授权 AI 等方式、尺寸、来源。T3 追加具体镜头路径、光照方案、后处理清单（不使用时明确写无）。学术用途另列主线、各章贡献、因果/对比/递进/总分/并列关系的图示计划，以及每章开头承上启下句。三项及分档补充齐备后，才通过“确认按此方案制作／提出修改意见”请用户确认。记录实际选择与确认依据，不把预选或等待当确认。方案或需求变化后重新确认。
5. **Build／构建**：运行 `--check-plan`，将用户实际确认与对应摘要记录进方案，再运行 `--build`。校验通过后组装选定等级的单文件，随后按已确认视觉方案完善正文、素材和交互。AI 生图只可在此最终素材制作阶段执行。学术概念关系用流程图/对比表/层级图/时间线等可核验图示表达，不堆文字；每章开头写显性过渡句。不要把原始模板换文字当成高完成度交付。
6. **截图验收**：按 tiers.md 的对应清单在桌面/窄屏、鼠标/键盘/减少动态效果条件下验收；T3 测帧率和异常降级。发现返工条件先修复并复测。结论仅允许“通过 / 小修（列清单）/ 返工（说明原因）”，学术用途须找未读过内容的真人看完复述，说不出逻辑主线则返工；未做真人测试列小修待补，不由 AI 自测替代。未验证项如实列出，不得假称通过。
7. **交付**：交付完整 `index.html`、改动说明和上述验收结论及证据；注明 T3 CDN 联网要求、静态降级、未测限制。发布、覆盖既有成品和合入仓库依用户授权范围执行。

## Operating Rules

- 等级由用户亲选，不擅自升级。用户说“随便”时课堂展示默认 T1、产品介绍默认 T2，明确告诉用户；其他用途继续询问。T3 永不默认，等级选择后必须另次明确确认。美术完成度与等级独立。
- 内容来源由用户选：用户提供／搜索整理／两者结合。已授权搜索就主动检索，无需强制上传材料；尚待用户材料时不擅自搜索替代。优先一手权威来源并保留可点击引用；不编造事实、产品参数、研究成果或个人经历。只有无法获取的必要信息才补问。`new.py` 记录授权，不自动搜索或生成正文。
- 默认用 SVG/CSS 程序化制作装饰；Canvas 粒子和动态纹理只用于 T3，复用单 rAF。国风用水墨渐变、印章 SVG、细框线；科技用网格、辉光边、等宽数据标签；赛博朋克用霓虹渐变、扫描线、噪点；扁平插画用几何与柔影；暗黑用暗角、细金线、克制辉光；极简/学术用留白、发丝线分隔，不增加装饰。纯装饰 aria-hidden、pointer-events:none；窄屏隐藏大装饰保留底色，不能隐藏教学内容图示。
- **内置 imagegen 可在用户明确授权后使用，无需用户 API key。** 在 intake 中先询问是否使用 AI，并说明用途（最终背景／贴图／装饰），记录具体范围，再取得明确授权。不提交、拒绝或未回应均不授权；只在完整视觉方案确认后的最终素材制作阶段调用。不得将 AI 图用于对标参考、效果图或方案效果依据。需要调用时按可用 imagegen 技能执行；不可用时说明情况，不自行替换为外部 API。
- AI 最终图片 base64 内联；每张原始图片及编码内容均 <500000 字节，超限压缩并检查清晰度。交付注明哪些素材 AI 生成、工具、用途、来源/生成说明与替换对应 img data URL 的方式。真实网络素材核验使用许可并署名，不把 AI 素材冒充照片或科研证据。
- CSS 和业务 JS 内联，最终项目仅 `index.html`，无需构建。T3 使用原模板锁定版本 `0.170.0`，不得浮动升级；风格不会改变等级。单文件并不表示 CDN 离线可用。
- 用户确认记录必须来自实际答复，脚本只校验字段与摘要，不证明授权或来源真实。不得为了绕过 Build 检查自填同意；遇到缺失确认时停在对应步骤。
